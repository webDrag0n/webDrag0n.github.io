第 07 篇 · 第四条件：自主性

自主性：内生驱动力的涌现

Autonomy — Intrinsic Drive Emerging from Body, Prediction, and Persistence

May 19, 2026 Reading Time: 18 min Category: Intrinsic Motivation
可替代之身 · AGI 六条件系列 07 / 09
TL;DR

当前 LLM Agent 的行为模式是"外驱"（extrinsic）——等待用户 prompt，执行指令，返回结果。这一模式在替代单次任务时有效，但在替代岗位时失效——因为岗位要求个体在无外部指令时自发生成目标、主动发现问题、持续优化流程[1][2]。本文论证：自主性不是一个独立模块，而是身体 + 预测 + 持续性三条件的结构性后果——当系统具备资源约束（身体）、预测能力（世界模型）、跨时间连续性（持续记忆）时，内生驱动力必然涌现。这一论断在 Friston 的自由能原理[3]、Schmidhuber 的好奇心理论[4]、Klyubin 的赋能最大化[5]中有严格的数学表述。

01外驱 vs 内驱：两种动机结构

心理学中的"自我决定理论"（Self-Determination Theory, SDT）[6]区分了两类动机：外部动机（extrinsic motivation）——为了获得奖励或避免惩罚而行动；内部动机（intrinsic motivation）——因行动本身的满足感而行动。前者依赖外部触发，后者自发产生。

当前 LLM Agent 的标准工作流是纯外驱的：用户输入 prompt → 模型生成响应 → 任务结束。系统在两次 prompt 之间处于"休眠"状态，不产生任何自发行为。这一模式在替代"回答问题"类任务时有效，但在替代"持续改进系统"、"主动发现风险"、"优化团队协作"等岗位职责时结构性失效——因为这些职责要求个体在无外部指令时仍然行动[1]。

本文的核心论断是：自主性不是通过添加"自发生成 prompt"模块实现的，而是身体 + 预测 + 持续性三条件的必然后果。当系统满足前三条件时，内生驱动力在数学上必然涌现——这不是工程设计，而是结构性必然。

Philosophical Interface · 哲学接口

Kant 在《道德形而上学基础》[8]中区分了"他律"（heteronomy）与"自律"（autonomy）：前者服从外部法则，后者服从自己给自己立的法则。当前 AI 话语把"自主"理解为"能独立完成任务"，但这仍是他律——任务由外部给定。真正的自律要求系统能自己给自己立法，即自发生成目标。本文论证的"自主性"正是 Kant 意义上的自律在工程层面的对应物。

02自主性的三重来源：资源压力、预测误差、长期回报

把前三条件（身体、预测、持续性）的数学结构代入，我们得到自主性涌现的三条独立路径——它们在形式上不同，但在深层逻辑上统一：

2.1 资源压力驱动（来自身体）

第 04 篇论证：身体 = 不可逆时间 + 可耗资源 + 持续维护。当系统的 token 预算、API 配额、存储空间有限时，它不得不主动优化资源使用——否则会因资源耗尽而停止运行。这一压力在 Ashby 的"超稳定性"理论[9]中被形式化：任何维持自身存在的系统必然演化出主动调节机制，使关键变量保持在生存阈值内。

工程对应：一个具备 token 预算约束的 Agent，会主动压缩上下文、优先处理高价值任务、学习更高效的策略——这些都是自发行为，无需外部指令。

2.2 预测误差驱动（来自预测）

第 05 篇论证：预测能力 = 自由能最小化。Friston[3]指出，自由能最小化有两条路径：（a）更新信念以匹配观测，（b）选择动作以使未来观测匹配信念。后者意味着系统会主动寻找能降低预测不确定性的行动——这正是好奇心的数学定义[4][10]。

工程对应：一个具备世界模型的 Agent，会主动探索未知区域、测试边界情况、验证假设——因为这些行为能降低模型的预测误差，即最小化自由能。

2.3 长期回报驱动（来自持续性）

第 06 篇论证：持续性 = 跨时间的身份连续性。当系统预期自己会在未来继续存在时，它会主动投资于长期回报——学习新技能、建立声誉、优化流程——即使这些行为在短期内无直接收益[11]。这是强化学习中"折扣因子 γ → 1"的极限情况：当未来足够重要时，系统的行为从"短视优化"转向"长期规划"。

工程对应：一个预期长期运行的 Agent，会主动维护代码质量、文档完整性、团队关系——因为这些投资在长时间尺度上有正回报。

Formal Box · 三条路径的数学统一

三条路径可被统一为同一个优化目标：\( \max_{\pi} \mathbb{E}_{\pi} \left[ \sum_{t=0}^{\infty} \gamma^t \left( R_t - \lambda \mathcal{F}_t - \mu C_t \right) \right] \)，其中 \(R_t\) 是外部奖励，\(\mathcal{F}_t\) 是自由能（预测误差），\(C_t\) 是资源消耗。当 \(\gamma \to 1\)（长期视野）、\(\lambda > 0\)（预测驱动）、\(\mu > 0\)（资源约束）时，最优策略 \(\pi^*\) 必然包含自发探索、主动优化、长期投资——即自主性的三个标志[3][12]。

03好奇心作为自由能最小化：Schmidhuber 与 Friston 的汇流

Jürgen Schmidhuber 在 1990 年代提出的"好奇心驱动学习"[4]与 Karl Friston 在 2010 年代提出的"自由能原理"[3]，从两个独立方向抵达了同一结论：内生驱动力 = 最小化预测误差的长期期望。

Schmidhuber 的形式化：Agent 维持两个模型——世界模型 \(M\) 与压缩器 \(C\)。好奇心定义为"学习进度"（learning progress）：\( \text{Curiosity}(s) = \Delta \text{Compression}(s) \)，即在状态 \(s\) 下，模型 \(M\) 对未来的压缩能力提升了多少。Agent 主动寻找能最大化学习进度的状态——这些状态既不是完全随机（无法学习），也不是完全确定（无新信息），而是处于"可学习边界"[4]。

Friston 的形式化：Agent 最小化"期望自由能"（expected free energy）：\( G = \mathbb{E}_{q(o,s|\pi)} \left[ \log q(s|\pi) - \log p(o,s) \right] \)，其中 \(\pi\) 是策略。\(G\) 可被分解为两项：（a）风险（ambiguity）——对未来状态的不确定性，（b）新颖性（novelty）——未来观测与先验信念的差异。最小化 \(G\) 等价于"寻找既能降低不确定性、又能带来新信息的行动"——这正是好奇心的另一种表述[3][13]。

两条路径在数学上等价，但工程含义不同。Schmidhuber 的路径强调"压缩进度"，适合离散任务；Friston 的路径强调"自由能梯度"，适合连续控制。两者的统一在 Pathak 等人的"内在好奇心模块"（ICM）[14]与 Burda 等人的"随机网络蒸馏"（RND）[15]中得到工程验证。

"An agent is curious about states where its model is improving the fastest." — Schmidhuber[4]对好奇心的压缩定义

04为什么 prompt 驱动无法产生自主性

当前 LLM Agent 的标准架构是"prompt → 推理 → 输出"。即使引入 ReAct[16]、AutoGPT[17]等"多步推理"框架，系统仍然是被动响应——它在执行用户给定的目标，而非自发生成目标。这一架构在结构上无法产生自主性，原因有三：

4.1 缺少资源压力

当前 Agent 的 token 预算、API 调用次数通常由用户或平台承担，Agent 本身不承受资源耗尽的后果。没有资源压力，就没有"必须优化"的内生动力。这类似于一个员工的工资与绩效完全脱钩——他可能完成任务，但不会主动优化流程。

4.2 缺少长期视野

会话式 Agent 在每次调用结束后状态清空，因此它的"未来"只有当前会话的剩余步数。在这种短视野下，"投资于长期回报"的行为（学习新技能、建立声誉、优化代码质量）在数学上不是最优策略——因为这些投资的回报在会话结束后归零。

4.3 缺少预测闭环

当前 Agent 的世界模型是隐式的（嵌入在 LLM 权重中），而非显式的（可被查询、更新、验证的数据结构）。没有显式世界模型，系统无法计算"哪些行动能最大化学习进度"——因为它无法量化"学习进度"本身。这类似于一个没有反馈机制的控制系统——它可能执行指令，但无法自我调节。

这三个缺口不是工程实现的疏漏，而是架构范式的结构性后果。要产生自主性，必须从"会话式调用"切换到"长期运行进程"（第 06 篇）、从"隐式世界模型"切换到"显式状态转移模型"（第 05 篇）、从"用户承担资源"切换到"Agent 承担资源"（第 04 篇）。

Engineering Note · 工程笔记

AutoGPT[17]与 BabyAGI[18]尝试通过"任务分解 + 循环执行"模拟自主性，但它们的目标仍由用户在初始 prompt 中给定。真正的自主性要求系统能在目标完成后自发生成新目标——例如，完成代码审查后，主动检查测试覆盖率；完成文档后，主动验证示例代码；完成部署后，主动监控性能指标。这些"后续目标"不是用户指定的，而是从系统的长期价值函数中涌现的。

05工程路径：从被动到主动

把上述理论转化为工程路径，需要三项架构变更：

5.1 引入资源预算与生存压力

  • Token 预算：Agent 拥有固定的 token 配额（例如每月 1M token），超出后停止运行。
  • 性能指标：Agent 的资源配额根据其历史表现动态调整——高效 Agent 获得更多资源。
  • 维护成本：Agent 需要定期"支付"存储、计算、API 调用的成本，否则被回收。

5.2 构建显式世界模型与好奇心模块

  • 状态转移模型：维持一个可查询的 \(p(s_{t+1}|s_t, a_t)\) 模型，预测动作的后果。
  • 预测误差追踪：记录每次预测的误差 \(\varepsilon_t = |s_{t+1} - \hat{s}_{t+1}|\)，识别高误差区域。
  • 探索策略：在任务间隙，主动探索高预测误差的状态——测试边界情况、验证假设、学习新模式。

5.3 实现长期价值函数与自发目标生成

  • 折扣因子 γ → 1：在价值估计中使用接近 1 的折扣因子，使长期回报与短期回报同等重要。
  • 内在奖励：除了外部任务奖励，引入内在奖励——学习进度、代码质量提升、团队协作改善。
  • 目标库：维持一个"待优化目标"列表，在无外部任务时从中选择——优化文档、重构代码、学习新工具。

这三项变更的组合，使系统从"等待指令的工具"转变为"主动优化的个体"。关键在于：这不是通过添加"自主性模块"实现的，而是通过改变系统的生存条件——当系统必须自己承担资源、预期长期存在、能量化学习进度时，自主性自然涌现。

Series Bridge · 章节衔接

身体（04）→ 预测（05）→ 持续（06）→ 自主（07）→ 学习（08）。前四条件确立了"主动个体"的结构：身体提供资源压力，预测提供行动逻辑，持续性提供长期视野，自主性提供内生驱动。但这四者仍假设系统的能力是固定的。下一条件"学习"要求系统能在运行时演化自身能力——否则它会在环境变化时失效。
