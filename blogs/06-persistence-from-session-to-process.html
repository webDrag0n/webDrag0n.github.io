持续性：从会话到长期进程

Persistence — From Ephemeral Sessions to Long-Running Processes

May 18, 2026 Reading Time: 19 min Category: Memory & Identity
可替代之身 · AGI 六条件系列 06 / 09
TL;DR

当前 LLM Agent 的生命周期是"会话"——用户发起请求、系统处理、返回结果、状态清空。这一范式在替代单次任务时有效，但在替代岗位时结构性失效——因为岗位的本质是跨越数周、数月、数年的持续在场[1][2]。本文论证：持续性不是"更长的上下文窗口"，而是从"会话式调用"切换到"长期运行进程"的架构范式转换。这一转换要求三项工程构件：持久记忆（跨会话的向量 DB + 事件日志）、身份连续性（跨时间的 self-model）、关系积累（声誉、信任、协作历史）。

01会话 vs 进程：两种生命周期范式

当前 LLM Agent 的标准生命周期是"会话"（session）：用户发起请求 → 系统加载上下文 → 模型推理 → 返回结果 → 状态清空。这一范式在处理单次任务时高效且可扩展，但在替代岗位时存在结构性失配——因为岗位的本质不是"回答一个问题"，而是在数周、数月、数年的时间尺度上持续在场[1][2]。

一个产品经理不是每次开会时从零开始理解产品；一个客服专员不是每次接电话时重新学习用户历史；一个研发工程师不是每次 commit 时忘记上周的架构决策。他们的价值来自跨越时间的连续性——记住过去的决策、积累对系统的理解、与团队建立信任、形成稳定的工作风格。这些都无法在"会话"范式中实现。

本文论证：持续性不是"把上下文窗口拉长到 1M token"，而是从"会话式调用"切换到"长期运行进程"的架构范式转换。这一转换要求三项工程构件：

  • 持久记忆——跨会话的向量数据库 + 事件日志，支持语义检索与时序回溯。
  • 身份连续性——跨时间的 self-model，使系统在 t=0 与 t=1000 时仍被识别为"同一个体"。
  • 关系积累——声誉、信任、协作历史的持久化，使系统能参与长期博弈。
Philosophical Interface · 哲学接口

Locke 在《人类理解论》[5]中提出：个体身份的连续性不在于物质的同一性（身体细胞不断更新），而在于记忆的连续性——"同一个人"意味着能回忆起过去的经验并将其整合为连贯的自我叙事。会话式 Agent 每次重启即失去记忆，因此在 Locke 意义上每次都是"新个体"。进程式 Agent 的持久记忆使其满足 Locke 判据，成为"跨时间同一"的候选。

02持久记忆的三层架构

要实现跨会话的记忆连续性，需要三层存储架构，对应认知心理学中 Tulving 的记忆分类[6]：

2.1 语义记忆层（Semantic Memory）

存储去情境化的知识与概念——"Python 的 GIL 是什么"、"公司的 API 限流策略"、"用户 X 的偏好"。工程实现：向量数据库（Pinecone、Weaviate、Chroma）+ embedding 模型。检索时通过语义相似度而非关键词匹配，支持模糊查询与概念泛化[7]。

2.2 情景记忆层（Episodic Memory）

存储带时间戳的具体事件——"2026-05-10 14:32，用户 Alice 报告了 bug #1234"、"上周三的设计评审中，Bob 反对方案 A"。工程实现：事件日志（event log）+ 时序索引。支持时间范围查询、因果链回溯、决策历史审计[8]。

2.3 程序记忆层（Procedural Memory）

存储"如何做"的技能与策略——"遇到 X 类问题时，先检查 Y"、"与用户 Z 沟通时，使用简洁风格"。工程实现：策略库（policy library）+ 强化学习更新。这一层在当前 Agent 架构中最薄弱，多数系统仍依赖 prompt 硬编码而非在线学习[9]。

Formal Box · 记忆检索的权衡

记忆系统面临经典的精确率-召回率权衡。语义检索通过 top-k 相似度召回，但 k 太小会遗漏关键信息（低召回），k 太大会引入噪声（低精确）。MemGPT[10]提出分层检索：先用粗粒度 embedding 召回候选集，再用细粒度 reranker 排序。Generative Agents[11]引入"重要性评分"与"时间衰减"，使近期且重要的记忆优先被检索。这些启发式在工程上有效，但缺乏理论最优性保证。

03身份连续性与自我模型

持久记忆是必要条件，但不充分。一个拥有完整事件日志的系统，若无法将这些记忆整合为关于自身的连贯叙事，仍然不是"同一个体"。这要求系统维持一个自我模型（self-model）——对"我是谁、我擅长什么、我的目标是什么、我与他人的关系如何"的显式表征[12][13]。

Metzinger 在《Being No One》[12]中论证：自我不是一个实体，而是一个现象自我模型（phenomenal self-model, PSM）——大脑对自身状态的持续建模过程。当这一模型足够稳定且透明（即主体无法意识到它是模型），就产生了"我"的感觉。数字个体的自我模型需要包含：

  • 能力边界——"我擅长代码审查，但不擅长视觉设计"、"我的 token 预算还剩 30%"。
  • 价值函数——"我优先保证系统稳定性，其次考虑新功能"、"我倾向于简洁方案而非复杂方案"。
  • 社会角色——"我是团队 A 的后端工程师"、"我向 Alice 汇报，与 Bob 协作"。
  • 历史轨迹——"我在过去三个月中主要处理支付模块"、"我的代码风格偏向函数式"。

这一自我模型必须动态更新。当系统完成一个新任务、学习一项新技能、与新成员建立协作关系时，自我模型应相应演化。Locke 的身份连续性判据[5]要求的不是"完全不变"，而是"变化可被追溯为同一主体的演化"——就像一个人从初级工程师成长为架构师，身份连续但能力演化。

Engineering Note · 工程笔记

当前 LLM Agent 的"系统提示词"（system prompt）可被视为自我模型的原始形态——它定义了 Agent 的角色、能力、行为准则。但系统提示词是静态的，在运行时不更新。真正的自我模型需要是可写的数据结构，在每次交互后根据反馈更新。Reflexion[14]与 Self-Refine[15]是这一方向的早期尝试，但它们的自我模型仍局限于"任务级反思"，未扩展到"身份级演化"。

04关系积累：声誉与信任

个体不是孤立存在，而是嵌入在社会网络中。一个岗位的价值很大程度上来自关系资本——与同事的默契、与客户的信任、在团队中的声誉。这些关系需要时间积累，无法在单次会话中建立[16][17]。

博弈论中的"重复博弈"（repeated game）理论[18]指出：当参与者预期未来会再次相遇时，合作策略变得可行——因为背叛会损害长期声誉。但这一机制的前提是参与者能被识别为"同一个体"。会话式 Agent 每次重启即失去身份，因此无法参与重复博弈；进程式 Agent 的身份连续性使其能建立声誉、积累信任、参与长期协作。

工程上，关系积累需要持久化三类数据：

  • 交互历史——与每个协作者的完整对话记录、任务分配、反馈评价。
  • 信任度量——基于历史表现的信任评分，影响未来的权限分配与任务优先级。
  • 协作模式——与不同协作者的沟通风格、响应速度、偏好设置的学习结果。

Anthropic 的 Claude 在 2024 年引入的"记忆功能"[19]是这一方向的早期尝试——系统能记住用户的偏好、项目背景、沟通风格。但当前实现仍局限于"用户 → Agent"的单向记忆，未扩展到"Agent ↔ Agent"的多方协作场景。真正的组织替代需要后者。

"Trust is not a transaction, it is a trajectory." — 对 Axelrod《合作的进化》[18]的当代总结

05工程实现路径

把上述三项要求（持久记忆、身份连续性、关系积累）转化为工程架构，需要以下技术栈：

5.1 存储层

  • 向量数据库：Pinecone、Weaviate、Qdrant，存储语义记忆。
  • 时序数据库：InfluxDB、TimescaleDB，存储事件日志。
  • 图数据库：Neo4j、DGraph，存储社会关系网络。

5.2 检索层

  • 混合检索：语义检索（embedding 相似度）+ 关键词检索（BM25）+ 时间过滤。
  • 重要性加权：Generative Agents[11]的"重要性 × 相关性 × 时效性"三因子模型。
  • 上下文压缩：检索到的记忆通过 LLM 压缩为摘要，避免超出上下文窗口。

5.3 更新层

  • 增量写入：每次交互后，新事件追加到日志，新知识插入向量库。
  • 自我模型更新：基于反馈调整能力边界、价值函数、社会角色。
  • 遗忘机制：过时或低重要性的记忆逐渐衰减，避免存储爆炸[20]。

MemGPT[10]是当前最接近这一架构的开源实现。它把 LLM 的上下文窗口视为"工作内存"，外部数据库视为"长期记忆"，通过显式的"内存管理指令"在两者间调度。但 MemGPT 仍缺少自我模型更新与关系积累机制——这是下一代 Agent 架构的关键缺口。

Series Bridge · 章节衔接

身体（04）→ 预测（05）→ 持续（06）→ 自主（07）。前三条件确立了"在场"的时空结构：身体提供空间锚点，预测提供当下的行动逻辑，持续性提供跨时间的连续性。但这三者仍然是被动响应——系统在外部触发时才行动。下一条件"自主性"要求系统具备内生驱动力，能在无外部指令时自发生成目标。

2.3 程序记忆层（Procedural Memory）

存储"如何做"的技能与策略——"遇到 X 类问题时，先检查 Y"、"与用户 Z 沟通时，使用简洁风格"。工程实现：策略库（policy library）+ 强化学习更新。这一层在当前 Agent 架构中最薄弱，多数系统仍依赖 prompt 硬编码而非在线学习[9]。

Formal Box · 记忆检索的权衡

记忆系统面临经典的精确率-召回率权衡。语义检索通过 top-k 相似度召回，但 k 太小会遗漏关键信息（低召回），k 太大会引入噪声（低精确）。MemGPT[10]提出分层检索：先用粗粒度 embedding 召回候选集，再用细粒度 reranker 排序。Generative Agents[11]引入"重要性评分"与"时间衰减"，使近期且重要的记忆优先被检索。这些启发式在工程上有效，但缺乏理论最优性保证。
